## Instalar o actualizar

1. **Identifica la entrega.** Consulta Releases y registra la revisión del DS que vas a instalar.
2. **Usa el namespace GRM.** Configura `@grm` en `components.json`. Inclúyelo en cada nombre del comando: `@grm/button`, `@grm/alert`, etc. Un nombre sin namespace puede resolver un componente genérico de shadcn.
3. **Revisa el diff.** Prueba primero en un consumidor limpio y compara los archivos antes de sustituir componentes personalizados.
4. **Conecta estilos y fuentes.** Importa `grm.css` desde la entrada CSS de la aplicación y carga las fuentes instaladas. El CLI copia los archivos, pero no completa esa conexión por ti.
5. **Aplica la marca.** Coloca `data-theme` en un ancestro que incluya los portales, preferentemente `html`.

Puedes instalar varios componentes en un comando; todos deben llevar su namespace.

Si un radio o color difiere, compara el token y la versión de origen. Documenta las excepciones del producto con su motivo y alcance antes de introducir un valor distinto.

## Revisar dependencias

El registro declara rangos compatibles. Al instalar, pueden cambiar paquetes compartidos como Base UI, Radix UI, Lucide o React DayPicker. Revisa `package.json` y el lockfile y conserva las versiones resueltas en tu control de cambios.

Stepper incluye su licencia como archivo independiente; mantenlo en el consumidor aunque el CLI transforme el código.
